Real-Time Streaming ML Pipeline

Context: Built production system to process vehicle telemetry in real-time, predict A/C energy consumption with sub-5ms latency, and serve 10M+ events daily with 99.97% uptime. This system powers predictive maintenance and energy optimization across vehicle fleet.

System Architecture

Why Kafka?

Need durable, replayable event stream. Kafka provides: partition-level parallelism (16 partitions = 4 independent consumers), durability for retraining, timestamp-based retention.

Alternative considered: AWS Kinesis (would require vendor lock-in, higher cost at this scale)

Why CatBoost?

Tabular ML on vehicle telemetry. CatBoost offers: categorical feature handling (engine_type, transmission), fast inference (4.2ms), strong performance on structured data.

Benchmark result: CatBoost R²=0.94 vs XGBoost R²=0.91 vs LSTM R²=0.79

Technical Challenges

Challenge 1: Late Arriving Data

Vehicle sensors may batch-upload telemetry hours later. How to handle out-of-order events?

Solution: Watermark-based windowing in Spark Structured Streaming. Allow 1-hour late arrivals, emit results every 5 seconds.

Challenge 2: Feature Consistency

Features computed in batch (for training) vs. streaming (for serving) diverged. Model drift.

Solution: Centralized feature store (Feast). Single source of truth for training & serving pipelines.
